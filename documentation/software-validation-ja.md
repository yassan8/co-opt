# co-opt ソフトウェア検証

## 目的と判定

新機能の数ではなく、既存機能について「どの入力を、何と比較し、どこまで確認したか」を残す。
本書は全機能の認証・全設計に対する精度保証ではない。

**2026-09-09 最終結果: 自動診断18グループ中17合格、1失敗（型検査335件）、別途確認が必要な7領域は未検証。**
[最終検証表](../.tmp/software-validation/2026-09-09T04-45-06-514Z-ccIKJN/report.html) ／ [実ブラウザの操作記録](software-validation-browser-20260909.md)
結果判定処理自体のテストは5/5合格。結果表のNodeメモリ指定は各commandの引数を正とする（最終実行後、ビルド/型検査への1536 MiB指定の有無を示すメタデータのみ訂正した）。

| 判定 | 意味 |
|---|---|
| 合格 | このケースの明示した条件・許容誤差を満たした |
| 失敗 | 実行したが条件を満たさなかった。時間超過も含む |
| 実行不可 | 起動できない、必要な入力がない、診断がSKIPした |
| 未検証 | 今回実行していない、または別の検証方法が必要 |

終了コード0だけでは合格にしない。`skipped: true`、Rustの実行テスト0件、完了結果の欠落を検出する。
各グループ内の件数は異なるため、グループ数を個別テスト数や全ソフトの検証完了と解釈しない。

## 再実行

依存関係をインストール済みのプロジェクトで実行する。Node.js 24を今回使用した。

```powershell
npm run verify:software:policy
npm run verify:software
```

Rust開発環境がある場合、ローカル版の計算核も含める。

```powershell
npm run verify:software:native
```

対象を絞る場合:

```powershell
npm run verify:software -- --only camera-independence,public-preflight
npm run verify:software -- --only michelson,fizeau
```

結果は毎回新しい `.tmp/software-validation/<実行日時>-<識別子>/` に作成する。過去の検証結果、設計JSON、追跡対象の `dist` は上書きしない。

- `report.html`: 日本語の検証表。数値根拠は展開して表示。
- `report.md` / `report.json`: 閲覧用と機械可読の結果。
- `inventory.json`: diagnostics / testing / tests 内の診断コードの棚卸し。ファイル数はテスト数やカバレッジ率ではない。
- `fingerprints.json`: 計算コード、診断、代表JSON、WASM等のSHA-256。作業中の未コミット変更を含む実行入力の識別に使う。
- `<検証ID>.log`: 各実行の標準出力とエラー。
- `checkpoint.json`: 各診断完了時点の途中結果。
- `analysis/`: 既存28項目の詳細結果。
- `build/`: 検証専用の配信用ビルド。デプロイはしない。

終了コードは、0=選択した自動診断が合格、1=失敗あり、2=実行不可あり。0でも別途確認が必要な項目は「未検証」のまま残る。
Node診断の親プロセスはold-space 1536 MiBを指定するが、TypedArray・WASM・子プロセスを含む総メモリ上限ではない。

## 最初に固定する代表ケース

| ケース | 参照と合格基準 | 確認できないこと |
|---|---|---|
| 平面・球面・放物面、Snell屈折 | `analysis-verification/foundation-checks.mjs` の解析解と量ごとの許容誤差 | 任意の非球面の全条件 |
| 座標変換・絞り・正負画角・近軸レンズ | 逆変換、瞳位置、符号、レンズ公式 | 操作画面の位置やラベル |
| default-load / 広角収差の公開例 | JS/WASMの交点、OPL、OPD比較と収差の連続性 | 同じ誤りを共有していないことの完全な証明 |
| 無収差円形瞳 | 解析MTF・瞳自己相関・PSFの正規化 | すべての収差での収束 |
| マイケルソン | 等長腕OPD誤差 < 1e-8 mm、ミラー1 µm移動→OPD 2 µm（誤差 < 1e-8 mm）、干渉波形RMS < 0.02 | 高NA、偏光、任意の多重反射 |
| フィゾー | 20 mm空気間隙→40 mm OPD、λ/4移動で干渉項反転（相対誤差 < 1e-5）、共通ガラスOPD相殺 | 多重反射を含む完全なFizeau、面形状の逆算 |
| 単色Cameraの光線数 | マイケルソンで4096→8192本、画像L1相対差 < 0.1 | 広帯域の波長数・Camera pitchを含む収束 |
| 人工Camera画像の形状復元 | 正解Targetを変更しても復元高さ・ridgeが完全一致、同一画像との差分高さ < 1e-8 µm、無信号被覆率0 | 実光学系を通したsin/tilt/Dual-combの定量精度 |
| 公開JSONの往復と破損 | JSON往復で経路一致、Config独立、Detector/Source/Port/接続欠落で実行不可、大画像を割当前に拒否 | Fileダイアログ・Undoの実画面操作、任意の古いJSON |
| 感度・公差の制御 | 既知の線形関数の微分誤差 < 1e-12、seed再現、逐次/バッチ一致、途中進捗 | 評価関数はスタブ。実Workerや実レンズの結果は別検証 |

基準値や許容誤差を、結果が不合格だからという理由だけで緩めない。基準の誤りが疑われた場合は、独立した根拠と変更理由を残す。
Targetは順方向の画像生成には使える。一方、復元側は測定画像と校正情報だけで動作させ、比較用正解形状は一致度の評価にのみ使う。

### 検出して修正した不具合

Detectorを削除し保存済み経路が残った入力で、`compileAutomaticAssemblyRouting` が存在しない部品を参照し例外停止していた。
また、削除された接続を飛ばして保存光路を短縮していたため、別の光路で結果が出る危険があった。

保存経路全体を検査し、不成立時は理由を返してpreflightで実行を止める。勝手な自動再探索へ切り替えない。
接続は有効で、キャッシュされたSource/Detector名だけが古い場合の従来の移行は維持する。
削除部品、削除接続、削除Port、古い端点メタデータ、正常な両干渉計を回帰対象に追加した。

続く実ブラウザ検証では、解析ウィンドウを開いた後のRequirementsの有効・無効がRunに反映されない不具合を検出した。
Run時の最新設定から選択を組み立て直し、Study保存時も最新の設定を保つよう修正した。
SensitivityのWASM Worker完了、公差100/100試行、Stop→再Run、有効・無効の再切替を確認した。
詳細は [実ブラウザ検証記録](software-validation-browser-20260909.md) を参照。

### 型検査は別途不合格

配信用Viteビルドは合格した一方、`tsc --noEmit --pretty false` は全体で不合格だった。
未定義の名前、型の不一致、重複定義、利用するJavaScript APIとTypeScript lib設定の不一致などを含む。
これをビルド成功で代用せず、検証コマンドに独立した失敗項目として追加した。
今回の変更以外にもエラーが広く分布している。どれが既存か・いつ発生したかの全件比較は未実施であり、全てを今回新規または全て既存とは断定しない。
修正前後の最終結果は新しい実行フォルダの `report.json` と `typecheck.log` を正とする。

## 残る優先項目

1. 実ブラウザのFile読込→編集→Undo/Redo→保存→再読込→解析→Renderまでを通す。DOMスタブの合格で代用しない。
2. 実WorkerでSensitivity/Toleranceの進捗・キャンセル・再実行を確認する。代替経路で動いた場合はその事実も記録する。
3. Cameraの連続Runでブラウザメモリの回収を観察する。予算超過の事前拒否はリーク対策の証明ではない。
4. 広帯域形状復元の光線数・波長数・pixel pitchの収束表を作る。正解形状を復元処理へ渡さない。
5. 同一ConfigのWeb/Tauri比較、条件を揃えた独立ソフト・実測との比較。
6. CIは現状PRの`main`向けビルド中心。名称が「Typecheck + Build」でも実コマンドはViteビルドであり、型検査や本検証一式の自動実行を意味しない。デプロイ対象ブランチも含む継続検証は別途整備が必要。
